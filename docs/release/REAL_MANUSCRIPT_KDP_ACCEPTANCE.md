# ScrollLibrary P11 — actual generated-book KDP acceptance (NO-GO until externally proven)

This checklist is the release-owner handoff for a **real**, complete, authorized manuscript generated by ScrollLibrary. The repository's Unicode integration fixture and `CI` passes are not a substitute for this campaign. Do not enable KDP-ready advertising, the public export gate, or publishing checkout from these mechanical checks alone.

## 1. Select a legitimate complete generated book

Use an owner-authorized book in the Lovable-controlled database, not another customer's unpublished manuscript without permission. A read-only metadata check can identify candidates; metadata counts do **not** authorize copying text or establish that it was created by the exact release candidate.

Record in your **private evidence workspace**:
- canonical exact release SHA, Lovable source SHA and hosted release identity;
- book UUID, owner consent, generation run/provider identity and expected chapter count;
- complete generated `chapters` content, ordered by chapter number and with `is_generated=true`, exported through the approved read-only path;
- complete chapter count and exact manuscript hash, before and after any edits;
- file-production origin, timestamps, per-format export event IDs and independently read-back raw SHA-256 hashes.

**Do not upload private manuscript content, user identifiers, payment tokens, backend keys, signed URLs or raw provider outputs to the public GitHub repository.** Work within a private, access-controlled evidence folder.

## 2. Obtain the actual exports

From the source-matched hosted product, use a consented account and the existing `export-book` function to obtain the ordinary PDF and KDP interior PDF from the **same manuscript scope**. Read back corresponding `exports` hashes through the Lovable control plane. Verify every export is bound to the expected published/draft integrity level; the new certified-export guard in PR #175 must be deployed on the verified exact head before it can be credited.

Source JSON expected by the verifier (private file only):

```json
{
  "book_id": "00000000-0000-4000-8000-000000000001",
  "release_sha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "chapters": [
    {"chapter_number": 1, "title": "Chapter 1", "content": "Complete generated content goes here", "is_generated": true}
  ]
}
```

The example above is only a schema illustration, **not** a qualifying manuscript. The checker expects at least ten chapters, at least 100,000 content characters and at least 100 lexical words per chapter for a representative long-form trial. All chapters must be present in order.

Ledger readback JSON (also private): `{"pdf":{"sha256":"<64-hex>","export_id":"<uuid>"},"kdp_pdf":{"sha256":"<64-hex>","export_id":"<uuid>"}}`. The script compares those operator-provided references to file bytes; it cannot prove they came from the real hosted database. That requires independent Lovable readback.

## 3. Run deterministic, privacy-minimized mechanical checks

Install Poppler commands `pdftotext`, `pdffonts`, `pdfinfo` and Python 3. Run from the repository root:

```bash
python3 scripts/verify-real-manuscript-kdp.py \
  --source-json /private/book.json \
  --pdf /private/scrolllibrary.pdf \
  --kdp-pdf /private/scrolllibrary-kdp.pdf \
  --ledger-json /private/export-ledger.json \
  --output-json /private/real-kdp-evidence.json
```

This reuses `pdf_font_evidence.py` (all fonts embedded/subset/Unicode-mapped) and `check-kdp-interior-geometry.py` (6×9, white paper, no bleed, **actual final page count**, inside/outside text bounds). It independently checks three deterministic, ordered 12-word lexical witnesses per source chapter in each PDF, along with covered Akan/Greek/maths glyphs. The witnesses are deliberately sampled and **cannot certify whole-book semantic completeness, images, table placement, charts, accurate captions, Hebrew visual direction or every code line**.

Reports contain only digests, counts, status codes, chapter ordinal positions and optional page geometry; **no verbatim manuscript passages**. The script returns nonzero when the available mechanical evidence fails. Even if it returns 0, `commercial_kdp_claim=NO_GO`, `kdp_previewer_acceptance=PENDING`, `independent_ledger_provenance=NOT_VERIFIED` and `actual_hosted_export_origin=NOT_VERIFIED` remain explicit.

## 4. Independent acceptance still required

1. Independently establish hosted exact-release identity and verify the file hashes / `exports` rows through Lovable read-only queries.
2. Assess **every** chapter against the full manuscript, including code/table/figure/bibliography and any footnote/citation blocks, not only lexical samples.
3. Render physical pages (at least front matter, odd/even gutters, page transitions, complex figure/table spreads and first/last chapters), inspect by a human, and record exact page numbers with no clipping, invisible text, unexpected blank pages or typographical errors.
4. Use the **actual** target KDP paperback specifications; the existing script checks only a 6×9 white-paper/no-bleed textual interior. Covers, color/cream/bleed variants require distinct approval.
5. Upload the representative actual interior PDF in **KDP Previewer** with the intended book specification and obtain the actual platform validation and visual review. Record dated acceptance, relevant screenshots, warnings (zero unresolved), reviewer and source/PDF hashes.
6. Rehearse the hosted long-book export resource/time budget and delivery audit: direct binary, storage fallback, audit readback and download SHA-256. Do not count a synthetic renderer benchmark as this.
7. Attach non-sensitive summarized evidence to issue #133 and the candidate commercial GA evidence pack. Human/platform proofs remain blocked until performed.

P11 remains **DISABLED** and commercial KDP-ready remains **NO-GO** until all seven steps pass on one final exact release candidate. Free/core GA is separately evaluated. This is not legal or retailer-policy advice.
